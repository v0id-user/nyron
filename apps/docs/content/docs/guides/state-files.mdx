# State Files

Nyron stores release bookkeeping in the `.nyron/` directory.

These files are generated by Nyron and should usually be treated as machine-managed state:

- `.nyron/meta.json`
- `.nyron/versions.json`
- `.nyron/meta.schema.json`
- `.nyron/versions.schema.json`

If a workflow is interrupted or you need to inspect the files manually, this guide explains the expected structure.

## `meta.json`

`meta.json` tracks the current version of each configured project plus the latest Nyron release boundary tag.

```json
{
  "$schema": "./meta.schema.json",
  "packages": [
    {
      "prefix": "cli",
      "version": "0.7.9"
    }
  ],
  "createdAt": "2026-01-01T00:00:00.000Z",
  "latestTag": "nyron-release@2026-01-01@00-00-00.000"
}
```

### Important notes

- `packages` is an **array**
- each entry must contain:
  - `prefix`
  - `version`
- fields like `name` and `path` belong in `nyron.config.ts`, not in `meta.json`

## `versions.json`

`versions.json` stores version history per configured project.

```json
{
  "$schema": "./versions.schema.json",
  "createdAt": "2026-01-01T00:00:00.000Z",
  "packages": {
    "cli": [
      {
        "prefix": "cli",
        "version": "0.7.8"
      },
      {
        "prefix": "cli",
        "version": "0.7.9"
      }
    ]
  }
}
```

### Important notes

- `packages` is an **object keyed by project id**
- each project value is an **array of objects**
- each history entry must contain:
  - `prefix`
  - `version`
- `lastPublished` is optional and only appears when Nyron records publish metadata

## Validation and Recovery

If you suspect `.nyron/` drift, run:

```bash
npx @nyron/cli validate
```

If the files are missing or stale, use:

```bash
npx @nyron/cli fix
```

## Source of Truth

Nyron refreshes `.nyron/` state from each project's `package.json` before version bumps. That makes `package.json` the authoritative source for the current version while `.nyron/` remains the release bookkeeping layer.
